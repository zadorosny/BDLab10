Respondidas: 0/20

C3-Q01. Na organização de uma loja, qual associação entre os conceitos relacionais está correta?

Situação: Você entrou em uma equipe de suporte a uma loja e precisa descrever onde os dados são organizados. O ambiente tem uma instância PostgreSQL, um banco chamado loja e uma tabela clientes com registros de pessoas. A ideia é distinguir os níveis, sem confundir a estrutura com seus dados.

Comentário: O servidor executa o SGBD e atende conexões; um banco contém objetos de uma aplicação; uma tabela organiza registros; uma linha representa um registro; uma coluna representa um atributo. Exemplo: servidor PostgreSQL → banco loja → tabela clientes → cliente Ana → coluna nome.

C3-Q02. Após executar CREATE TABLE contatos (nome VARCHAR(50), idade INTEGER), sem outras operações, qual é o estado esperado?

Situação: Antes de importar contatos, um colega executou apenas CREATE TABLE contatos (nome VARCHAR(50), idade INTEGER). Nenhum INSERT foi executado e a criação terminou com sucesso. Você vai conferir o que esse comando preparou para a carga.

Comentário: Define nome e estrutura da tabela, incluindo colunas, tipos e eventuais restrições. CREATE TABLE comum cria uma tabela vazia.

C3-Q03. Qual é a principal vantagem de usar INSERT INTO contatos (nome, idade) VALUES ('Ana', 22)?

Situação: Um script de cadastro será mantido por outras pessoas, e a tabela poderá ganhar colunas. Você revisa um INSERT com lista explícita de campos e quer entender o benefício dessa forma, mesmo quando os dados atuais cabem em todas as colunas.

Comentário: A lista explicita o mapeamento valor–coluna e reduz dependência da ordem física declarada. Valores trocados podem causar erro de tipo ou, quando compatíveis, armazenar dados incorretos silenciosamente.

C3-Q04. Sem DISTINCT nem filtros, o que muda ao trocar SELECT * FROM clientes por SELECT nome, cidade FROM clientes?

Situação: Um relatório precisa apenas do nome e da cidade, mas sua primeira versão retorna todos os campos do cadastro. Você quer reduzir a largura do resultado sem excluir nenhum cliente e sem eliminar repetições.

Comentário: * retorna todas as colunas; a lista retorna somente as indicadas. Isso não filtra linhas; use WHERE para selecioná-las.

C3-Q05. Qual filtro seleciona idades maiores ou iguais a 18 e estritamente menores que 30?

Situação: Uma campanha atende pessoas que já completaram 18 anos, mas ainda não chegaram aos 30. A coluna idade contém inteiros e a regra de elegibilidade exige atenção aos dois limites, inclusive para quem está exatamente no aniversário de 18 ou 30 anos.

Comentário: WHERE idade >= 18 AND idade < 30. Inclui 18, exclui 30; com idade inteira, vai de 18 a 29.

C3-Q06. Considere uma tabela simples, sem regras ou restrições que impeçam a operação. Qual o alcance de UPDATE e DELETE sem WHERE?

Situação: Um aluno está revisando comandos de alteração em uma tabela de treinamento com várias linhas. Ele removeu por engano a cláusula WHERE de um UPDATE e de um DELETE. Antes de executar, precisa compreender o alcance de cada operação.

Comentário: Sem filtro, o comando tenta atualizar ou excluir todas as linhas da tabela. Restrições, permissões ou outros mecanismos podem impedir a operação; a ausência de filtro não a limita a uma linha.

C3-Q07. Qual diferença descreve corretamente DELETE FROM contatos e DROP TABLE contatos?

Situação: Ao encerrar um exercício, a equipe pode precisar esvaziar uma tabela para reutilizá-la ou remover completamente o objeto de teste. Os dois objetivos parecem semelhantes, mas têm efeitos diferentes sobre a estrutura disponível na próxima sessão.

Comentário: DELETE remove linhas e mantém a estrutura. DROP TABLE remove o próprio objeto, sujeito a dependências.

C3-Q08. Como garantir a apresentação por cidade crescente e, dentro de cada cidade, por idade decrescente?

Situação: O relatório de contatos será conferido por cidade. Dentro de cada cidade, os mais velhos devem vir primeiro. O fato de os dados terem sido inseridos em uma certa sequência não deve ser usado como garantia de apresentação.

Comentário: Não há ordem garantida sem ORDER BY. Use ORDER BY cidade ASC, idade DESC; acrescente uma chave única se precisar desempatar totalmente.

C3-Q09. Em SQL PostgreSQL, como interpretar 'Ana' e "Ana"?

Situação: Um erro em uma consulta de cadastro faz o servidor procurar uma coluna chamada Ana, embora a intenção fosse comparar o nome com esse texto. Você revisa o papel das aspas usadas na condição, não a capitalização dos dados armazenados.

Comentário: Aspas simples delimitam um literal de texto. Aspas duplas delimitam identificadores, por exemplo "Nome Completo"; "Ana" seria um identificador, não o texto Ana.

C3-Q10. Antes de um DELETE com filtro, qual conferência ajuda a identificar um conjunto de linhas incorreto?

Situação: Uma rotina precisa excluir uma parte dos registros. Antes de alterar dados, você deve conferir se o filtro representa a intenção do pedido. O ambiente pode ter outras sessões, portanto a conferência também não deve ser confundida com uma garantia de imutabilidade até o DELETE.

Comentário: Execute SELECT * e/ou SELECT COUNT(*) com o mesmo WHERE e confira os registros. Isso detecta filtros amplos ou incorretos; em ambiente concorrente, a conferência prévia por si só não congela o conjunto de linhas.

C3-Q11. Qual é o efeito esperado dessa inserção?

Situação: Uma tabela de contatos de teste possui as colunas nome VARCHAR(50), cidade VARCHAR(50) e idade INTEGER, nessa ordem. A aplicação recebeu os dados Ana, Curitiba e 22. O desenvolvedor escreveu INSERT INTO contatos VALUES ('Curitiba', 'Ana', 22). Não há restrições adicionais.

Comentário: Sem lista de colunas, os valores seguem a ordem declarada. O sistema verifica tipos e restrições, não o significado de um nome ou cidade. Como ambos são textos válidos, esse erro pode passar silenciosamente. Prefira INSERT INTO contatos (nome,cidade,idade) VALUES ('Ana','Curitiba',22).

C3-Q12. Qual consulta retorna somente os nomes desses dois contatos com base na idade?

Situação: Em uma base de teste há três contatos: Ana, 22 anos; Bruno, 31; e Carla, 27. Um analista quer localizar apenas Ana e Carla antes de revisar seus cadastros.

Comentário: SELECT nome escolhe a coluna apresentada; WHERE idade < 30 escolhe as linhas de Ana e Carla. Selecionar idade muda a coluna de saída; ORDER BY apenas ordena; uma única idade não pode ser simultaneamente 22 e 27.

C3-Q13. Qual comando faz a alteração solicitada sem atingir a outra Ana?

Situação: Uma tabela de ensaio tem os registros (id=1, nome=Ana, cidade=Curitiba) e (id=2, nome=Ana, cidade=Santos). Somente o cadastro de id 2 deve mudar de cidade para Recife. O id identifica cada contato de forma única.

Comentário: O filtro pela chave id=2 identifica exatamente a linha desejada. O filtro pelo nome atingiria as duas pessoas; a ausência de WHERE atingiria todas; alterar nome ou manter Santos não cumpre a solicitação.

C3-Q14. Qual comando usa corretamente o limite solicitado?

Situação: Um script de teste contém quatro contatos com idades inteiras não nulas: 17, 18, 19 e 25. A tarefa é remover apenas os menores de idade, preservando quem já completou 18 anos.

Comentário: Menor de 18 corresponde a idade < 18. O operador <= também excluiria quem tem 18; <> removeria todas as outras idades, inclusive adultos. A diferença entre limites inclusivos e exclusivos é decisiva nas alterações de dados.

C3-Q15. Qual ORDER BY garante cidade crescente, idade decrescente e desempate final por id crescente?

Situação: Um relatório de ensaio precisa ordenar pessoas da mesma cidade pela idade, mantendo a ordem estável mesmo quando há pessoas da mesma idade. Cada contato tem um id único.

Comentário: As chaves de ordenação são aplicadas da esquerda para a direita. O id único elimina o empate restante entre cidade e idade. Sem esse último critério, duas pessoas empatadas podem aparecer em qualquer ordem relativa.

C3-Q16. O que ele pode fazer em seguida?

Situação: Depois de executar DELETE FROM rascunho, um aluno quer reutilizar a tabela vazia para uma nova tentativa. O comando terminou com sucesso, e nenhuma outra operação alterou a estrutura.

Comentário: DELETE elimina linhas, não tipos, colunas ou a tabela. Um novo INSERT pode reutilizá-la. Criar outra tabela com o mesmo nome no mesmo schema causaria conflito. Preservar a estrutura não recupera os registros removidos.

C3-Q17. Qual interpretação do erro é adequada?

Situação: Um iniciante executa SELECT sobrenome FROM contatos, mas a tabela contém somente id, nome, cidade e idade. A conexão está correta e a tabela existe.

Comentário: A lista de colunas é definida na estrutura da tabela. SELECT não cria colunas e uma tabela vazia continua tendo estrutura conhecida. Confira a definição — por exemplo com a interface do cliente ou com \d contatos no psql — e ajuste a consulta.

C3-Q18. Qual consulta controla diretamente a ordem das colunas na saída?

Situação: Um arquivo de exportação precisa ter cidade na primeira coluna e nome na segunda. A tabela contatos foi criada com nome antes de cidade. Nenhuma transformação de dados é necessária.

Comentário: A ordem das expressões na lista SELECT define a ordem das colunas retornadas. ORDER BY controla a sequência das linhas, não a posição das colunas. Não é necessário recriar a tabela para mudar essa apresentação.

C3-Q19. Quais idades ficam armazenadas ao final?

Situação: Uma tabela simples de teste contém idades 18, 22 e 30. O aluno executa UPDATE contatos SET idade = idade + 1 WHERE idade >= 22. Todas as operações são permitidas e os valores cabem no tipo INTEGER.

Comentário: O filtro seleciona as linhas que tinham 22 e 30; cada uma recebe seu próprio valor anterior acrescido de um. A linha de idade 18 não satisfaz o WHERE e permanece intacta. A expressão de SET não atribui o mesmo literal 1 a todos.

C3-Q20. Qual consulta atende ao pedido?

Situação: Uma revisão pede o nome dos contatos que não moram no estado PR. Nesta tabela de teste, uf é sempre preenchida e contém somente códigos válidos. O analista quer filtrar linhas, sem mudar a tabela.

Comentário: <> significa diferente. A premissa de uf sempre preenchida evita a questão adicional de NULL, que não satisfaria a comparação. ORDER BY não exclui registros e DELETE altera a tabela em vez de produzir somente o relatório.

Atualizações em relação à edição histórica

  • O VACUUM comum disponibiliza espaço para reutilização interna e em geral não compacta todo o arquivo nem devolve todo o espaço ao sistema operacional. VACUUM FULL reescreve a tabela e exige bloqueio exclusivo. A descrição histórica do livro não deve ser aplicada literalmente. Consulte a documentação de VACUUM.
  • ANALYZE atualiza estatísticas; VACUUM (ANALYZE) também faz a limpeza. Há manutenção automática por autovacuum; veja manutenção rotineira.
  • Restrições PRIMARY KEY e UNIQUE criam índices automaticamente; uma FK não cria automaticamente índice no lado que referencia. Veja restrições.
  • A eficiência de índices B-tree compostos depende das condições, ordem de colunas e distribuição. Há possibilidades de uso sem filtro na primeira coluna, inclusive skip scan no PostgreSQL 18. Veja índices multicoluna.
  • CLUSTER exige ACCESS EXCLUSIVE, espaço de trabalho e não mantém a organização em novas escritas. A ordem de apresentação exige ORDER BY. Veja CLUSTER.
  • EXPLAIN (ANALYZE, BUFFERS) executa a consulta e mostra medições; neste material é usado com SELECT. Veja leitura de planos.
